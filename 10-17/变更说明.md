# 10-17 变更说明：中心站点监控 + 监控页优化 + 断线区间修复

## SQL 变更

**无**。本次未改任何表结构/菜单，无需执行 SQL。
（`teams_webhook` 列由此前 `00_all.sql` 提供，本次仅改其用途注释，不动数据库。）

## 一、中心化健康度监控（一台服务器监控全部采集点 + 邮件告警）

背景：原 `teams_offline_notify_flow.json` 是单站点硬编码（site_id 写死），且公司封禁 Teams webhook。
改为：中心服务器部署一个流轮询全部采集点，断线/恢复发邮件；现场节点零改动，新站点登记后自动纳入。

### 后端（需重启后端一次加载新路由；之后纯查库，新站点自动纳入）

- `module_site_health/service/site_health_service.py`
  - 新增 `get_site_status_all()`：全量站点状态快照（复用 `_decorate_row` 的 3×心跳间隔在线判定），
    返回 `id/siteName/building/floor/contact/notifyTarget/status/hasReported/isOnline/lastHeartbeat/heartbeatInterval/offlineSec`。
- `module_plc/controller/monitor_controller.py`
  - 新增 `GET /monitor/site-status-edge`（仅 X-API-Key，与 `/offline-intervals-edge` 同款写法）。

### 通知地址复用 teams_webhook 字段（按值自动区分）

- 值以 `http(s)` 开头 = Teams webhook；否则 = 邮箱地址。
- 后端 VO/DO 字段注释改为「断线通知地址：告警邮箱 或 Teams Incoming Webhook」（仅注释，无格式校验，邮箱可直接存）。
- 前端 3 处表单标签「Teams Webhook」→「通知地址」：
  `siteRegister/index.vue`、`siteHealth/register/index.vue`、`siteHealth/monitor/index.vue`。

### Node-RED 流

- 新增 `site_status_watch_flow.json`（本文件夹）：
  每 60s 轮询 `/monitor/site-status-edge` → 状态变化判定（flow context 基线，首轮只建基线不补报，离线 <60s 防抖，
  停用/未接入跳过，基线后新出现的离线站点直接告警）→ 逐条拼邮件 → e-mail 节点。
  收件人：优先站点登记的「通知地址」（邮箱时直接用；webhook 值退回兜底），兜底为 function 首行 `RECIPIENTS`。
  **前置**：中心服务器需 `npm i node-red-node-email`，e-mail 节点凭据不随流导出，导入后手工填 SMTP。
- `teams_offline_notify_flow.json` 保留，tab 说明标注「已弃用，供 webhook 解禁后参照」。

## 二、存量监控页表格优化（siteHealth/monitor/index.vue）

- 主表列序：采集场所 | 联系人 | 来源 | 办公网IP:端口 | 状态 | 心跳间隔 | 最近心跳 | 进程内存 | 整机已用 | 运行流数 | 运行时长 | 操作。
  多列 min-width 弹性分摊多余宽度（原「采集场所」单列吃光剩余宽度）。
- 来源列：彩色 el-tag → 灰字纯文本+图标（与状态列视觉区分）。
- 最近报错：独立列删除，并入操作列「报错」按钮（有报错时橙色带数量，无则灰色可点）。
- 操作列只留查看类：履历/趋势/上传记录/报错（270→280px）；
  管理类 4 按钮（修改/重置密钥/启停/删除）移入展开行底部按钮区。
- 展开行内容：位置、工业网IP、上报IP、采集点标识、Node-RED 版本 + 管理按钮区。
- 履历/上传记录抽屉：切换采集点时先清空旧数据 + 断线区间表加 loading（修复「点 B 先闪 A 数据」）。

## 三、断线区间推导修复

1. **近期断线查不出的 bug**：`site_health_dao.get_heartbeat_logs_asc` 原为「升序 + limit 5000」，
   7 天 30s 心跳 2 万余条时只保留最老约 1.7 天，最近履历被截掉。
   修复：倒序取最新再反转（截断只丢最老数据）；service 层 limit 改为按「时间跨度 ÷ 心跳间隔 + 200」自适应。
2. **短维护间隔混入断线区间**（重启后端/重新部署造成几分钟断档）：
   `get_offline_intervals` 新增 `min_sec` 参数（管理端 + edge 端，默认 0 不过滤，向后兼容）；
   前端「断线区间」页签默认只显示 ≥5 分钟区间，新增「含短间隔(<5分钟)」开关切回全量；
   顶部当前状态标签不受过滤影响。

## 生效方式

- 后端：重启服务（新路由 + 断线区间修复）。
- 前端：`dist` 已用 `vue-cli-service build --mode production` 构建通过，部署后刷新页面即可（无菜单/权限变更，无需重新登录）。
- 中心告警流：导入中心服务器 Node-RED，按流内「配置说明」填后端地址/X-API-Key/兜底收件人/SMTP。
