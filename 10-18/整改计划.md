# EdgeLink 生成器整改计划（三周执行版 · 逐日详细）

> 由两周版改写。三周 = 15 个工作日，按单人主线排；两人可压缩到两周（见文末）。
> 只改**生成器 + 生成的 flows.json + 部署/安全逻辑**，不改 MC 节点包（唯一可选改包点是 P0-2，默认走 `connect` 心跳方案，不碰包）。
> 每天一节，含「当天要做什么」+「当天结束如何验证」。验证不过则按 §7 停止规则处理，不带着半成品进下一天。

## 0. 两周 → 三周改了什么（关键修正）

| 两周版的坑 | 三周版处理 |
|---|---|
| 72h 浸泡放 Day 12-13，只有 48h | 浸泡 Day 13 启动，跨到 Day 15 满 72h（周末再延） |
| 试点要求「含 DOUBLE」，但 P0-3 拒绝 DOUBLE | DOUBLE 改为**拒绝用例**，不当采集点 |
| `ReadBlock` 轮询周期放设备级，Modbus 是块级 | Phase 1 就给 `ReadBlock` 加可选 `poll_ms?` |
| 黄金「逐字节一致」过严 | 改 **canonical 深比较 + 显式 ignore 列表** |
| 验收矩阵 `M200.0/M200.3` 预期没写死 | 逐条写死（见 §4） |
| Day 7 一天塞 P0-4a+P0-5+P0-6 | 拆到 Day 9-12 |
| 没有 Day 0 | Day 0 冻结/基线/备份/存量 tag 审计 |

## 1. 目标与边界

**目标**：把 MC 地址语义收回驱动内部，形成 `IR（ReadPlan/ReadBlock） + ProtocolDriver + fixture 契约测试` 的可扩展结构；同时修完当前 P0 数据契约/部署/安全问题。

**边界（对外表述）**
- 以后加协议 = 新增 `drivers/xxx.py` + `fixtures/xxx.json` + 后端声明的地址 schema，扩展点不动通用管线；
- 通用管线只负责：inject/调度、join、契约报文、质量/计数、MQTT/PG/link out；
- 每个 driver 必须提供 `capabilities`：`required_modules / addressFormat / supportedTypes / bitOffsetAllowed / blockMax / endianness / volatileFields / errorClassifier`；
- driver 方法接口（本次必须定义）：`validate / parse_address / plan_blocks / render_read / expected_key / extract / type_spec`；
- `ReadBlock` 结构：`{key, address, tags, poll_ms?}`——`poll_ms` 缺省走设备级，块级可覆盖（Modbus 用）；
- fixture 必须含 negative cases，且锁定真实包版本。

### Day 6：P0-1 —— 位设备契约

**做什么**
1. 定死位设备 `bit_offset` 语义（三选一，推荐第 3 种）：`register_address`=基位号 + `bit_offset`=偏移，全局位 = `addr + bit_offset`；写进 driver 文档和 fixture。
2. 改 `plan_blocks`：按 `register_type` 分流——
   - 位设备（M/L/F/V/X/Y/B）走「位号连续」分支，地址串 `M{start}` / `M{start},{count}`，**不带 `.bit`**；
   - 字设备（D/W/R）BIT 才走「字 + 位」分支，地址串 `D{addr}.{bit:X}`。
3. 改 `expected_key`/`extract`：位设备 key = `{reg_type}{global_bit}`；字设备 BIT key = `{reg_type}{addr}.{bit:X}`；不再无条件拼 `.bit`。
4. `validate` 拦截：位设备 `bit_offset>0` 若未定义语义则报错；字设备 `bit_offset` 必须在 0-15。
5. 升级冒烟断言（`test_flowgen_smoke.py`）为「地址 + 预期 key 集合」双断言；重录黄金快照。

**当天验证**
- ✅ `python ruoyi-fastapi-backend/scripts/test_flowgen_smoke.py` 全绿，且断言不再是纯字符串：
  - `M200`（bit_offset=0）→ address `M200`、key `M200`；
  - `M200/M201/M202` → address `M200,3`、keys `M200/M201/M202`；
  - `M200`+offset=3 → address `M203`、key `M203`（若采用第 3 种语义）；
  - `D100`+bit=3 → `D100.3`；`D100.3,4` → keys `D100.3~D100.6`。
- ✅ `python ruoyi-fastapi-backend/scripts/test_flowgen_golden.py` 重录后绿。
- ✅ 用 Day 1 探针的 `.expected.json` 反向核对：生成器产出的 address 与探针实测的输出键一致。
- ❌ 任何一个 key 不匹配 → 当天不结束。

### Day 8：P0-3 —— 类型与地址

**做什么**
1. `_MC_TYPE_PREFIX` 补 `UINT16: 'UINT'`（generator_service.py:34）；`type_spec('UINT16')` 返回 `('UINT', 1)`。
2. `validate` 拒绝 `DOUBLE`：报「当前 MC 包不支持 8 字节 DOUBLE，请改 FLOAT 或拆两个 32 位」，不静默降级。
3. 新增统一 `parse_address()`，按 `register_type + plc_series + octalInputOutput` 返回整数，替换 `_validate_inputs`（generator_service.py:101-139）、`_merge_blocks` 排序（:182）里的 `int(addr)`；复用 `tag_service.py:56-82` 的进制规则（W/B、非 FX X/Y 十六进制；FX X/Y 八进制；其余十进制）。
4. FX X/Y：八进制换算后以十六进制下发，且 `render_read` 的地址串与 `expected_key` 的 key 用同一套换算，避免「读/查不一致」。
5. 字节序/字序：确认包不消费 `byte_order/word_order`，生成期禁止非默认值（或真机验证后再放行），不假承诺。

**当天验证**
- ✅ 冒烟新增并全绿：`DUINT100`（无符号，负值变正值）、`DREAL100` 报错/拒绝、FX `X10`→十六进制换算、`W1A`/`B1A` 不再 `int()` 报错。
- ✅ `_validate_inputs` 对含 A-F 的 W/B/X/Y 地址不再误报「非数字」。
- ✅ `grep -n "int(addr)\|int(t\['register_address'\])" module_flowgen/` 在 service 层无残留，全走 driver 的 `parse_address`。

## 4. 验收矩阵（预期写死）

| 类别 | 必过用例 |
|---|---|
| 位设备 | M/X/Y/B/L/F/V 各 1 个 BIT；`M200.0`→`M200`；`M200.3`→`M200`；`M200.0,4`→`M200~M203`；`M200.3,4`→`M200~M203`；`D100.3`→`D100.3`；`D100.3,4`→`D100.3~D100.6` |
| 类型 | `DUINT100`=40000（无符号）；INT16/INT32/UINT32/FLOAT 边界；DOUBLE 拒绝 |
| FX | X10/Y10 与编程口一致；W/B 含 A-F 地址（探针不通过则明确拒绝 FX X/Y） |
| 重连 | 先 NR 后 PLC、先 PLC 后 NR、运行中重启 PLC/拔网线；10-30s 内恢复 |
| 部署清理 | 删设备/删 PG 目标/自定义前缀/手工复制 tab/移动节点后无残留，用户自建 tab 不动 |
| 凭证 | 重部署后 PG 仍可写；下载无明文；开启 adminAuth 后部署/包检查/凭证下发正常 |
| 语义 | 键缺失看到 UNCERTAIN/计数而非 GOOD；`value_count`=配置总数，`good_count`=实际有效值 |
| 浸泡 | 72h 无丢轮、无跨轮脏数据；断线恢复时间、部署中断时长、PG 成功率、UNCERTAIN 计数记录在案 |
| Modbus | （第 4 周）四类寄存器 100 轮不混轮；FC 命名以包实际枚举为准 |
| 断库 | 断库 5 分钟丢数范围（有/无 spool，或书面接受丢数） |

## 5. 准入门槛

- P0-1 契约测试必须在 CI 里对**真实节点包**跑，不能只比地址字符串；
- P0 全绿前，不建议用于含位设备、DOUBLE、UINT16、FX 的生产现场；
- 试点必须含 join 失败/断线恢复用例，不能只验证正常采集；
- 浸泡复盘通过前，只发 MC 单站试点，不宣称多协议/全量生产就绪。
