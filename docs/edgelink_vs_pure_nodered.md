# EdgeLink vs 纯 Node-RED 拖拽 — 架构对比分析

> 2026-06-07

---

## 一、纯 Node-RED 拖拽方式的局限

传统做法是直接在 Node-RED 编辑器里拖 MC Protocol / Modbus 节点，手动填写 PLC IP、端口、寄存器地址。

```
Inject → MC Read(D100, IP=192.168.1.100:5007) → Debug
Inject → MC Read(D200, IP=10.81.8.20:5007)    → Debug
Inject → MC Read(X0,   IP=192.168.1.100:5007) → Debug
...
```

| 痛点 | 表现 |
|------|------|
| **配置散落** | 20台PLC × 50点位 = 1000个节点或1000行硬编码配置，散落在各个 flow 里 |
| **改一个IP** | 需要找到所有引用该PLC的节点，逐个修改，漏一个就采集失败 |
| **无审计** | 谁改了配置？什么时候改的？Node-RED 不记录 |
| **无权限** | 任何人打开 `:1880` 就能改配置，工厂现场无法管控 |
| **无版本** | 改错了只能靠记忆恢复，没有软删除、没有变更历史 |
| **批量操作** | 改20台PLC的采集周期？一台一台找到节点改 |
| **新增设备** | 拖节点 → 填IP → 填端口 → 填帧格式 → 填站号 → ... 重复20+个参数 |
| **导入导出** | Node-RED 只有 flow JSON 导入导出，没有业务化的 Excel 模板 |

## 二、EdgeLink 架构能做到的

```
┌─────────────────────────────────────────────────────────┐
│  RuoYi Web UI（配置层）                                  │
│  ┌─────────────┐  ┌────────────┐  ┌──────────────────┐ │
│  │ PLC设备管理  │  │ 数据点表    │  │ 权限/审计/字典   │ │
│  │ 增删改查     │  │ 批量修改    │  │ JWT RBAC @Log   │ │
│  │ 启停/克隆    │  │ 导入/导出   │  │ sys_oper_log    │ │
│  └──────┬──────┘  └─────┬──────┘  └──────────────────┘ │
└─────────┼───────────────┼───────────────────────────────┘
          │ 写入           │ 读取
          ▼                ▼
┌─────────────────────────────────────────────────────────┐
│  MySQL / PostgreSQL（配置存储）                           │
│  plc_device (25字段) + plc_tag (15字段)                  │
│  status + del_flag 两级状态体系                           │
│  6个索引优化 Node-RED 查询                                │
└──────────────────────┬──────────────────────────────────┘
                       │ 每1-5秒拉取
                       ▼
┌─────────────────────────────────────────────────────────┐
│  Node-RED 采集引擎（运行时）                              │
│  ┌──────────┐  ┌───────────┐  ┌──────────────────────┐ │
│  │ 读配置SQL │→│ 采集调度器  │→│ MC Read / Modbus 等   │ │
│  │ 动态拉取  │  │ 按scan_ms │  │ 地址来自 msg.payload  │ │
│  └──────────┘  └───────────┘  └──────────────────────┘ │
└─────────────────────────────────────────────────────────┘
```

### 2.1 配置管理能力（纯 Node-RED 做不到的）

| 功能 | 说明 | 对应 API |
|------|------|---------|
| **Web 界面管理** | 表格+表单，非技术人员也能配置 | `/plc/device` `/plc/tag` |
| **模糊/精确筛选** | 按设备名称、IP、品牌、状态筛选 | `GET /plc/device/list` |
| **软删除** | 删错了可以恢复（改 del_flag 即可） | `DELETE /plc/device/{ids}` |
| **启停开关** | 临时停采某设备/点位，数据保留 | `el-switch` 一键切换 |
| **克隆设备** | 复制整台设备+全部点位，只改名称和IP | `POST /plc/device/clone/{id}` |
| **批量修改点位** | 勾选N个点位 → 同时改类型/单位/状态 | `PUT /plc/tag/batch` |
| **Excel 导入** | 按模板填好点位 → 一键导入，返回成功/失败明细 | `POST /plc/tag/import/{device_id}` |
| **Excel 导出** | 导出设备清单（19列），备份/归档 | `POST /plc/device/export` |
| **表单联动校验** | RS-232C 自动隐藏IP字段，FX系列禁用4E帧 | 前端 `onComTypeChange` |

### 2.2 企业级能力（纯 Node-RED 完全没有的）

| 能力 | 实现方式 |
|------|---------|
| **RBAC 权限** | 8个权限码：`plc:device:list/add/edit/remove` + `plc:tag:list/add/edit/remove`，不同角色看到不同按钮 |
| **操作审计** | `@Log(title='PLC设备管理', business_type=INSERT/UPDATE/DELETE/IMPORT/EXPORT)` 自动记录到 `sys_oper_log` |
| **JWT 认证** | 所有 API 需要登录 token，Node-RED 通过 HTTP 节点调用也需要 token |
| **数据字典** | 品牌、系列、通信方式等可扩展为字典表，统一维护 |
| **多数据库** | `.env` 切换 MySQL/PostgreSQL，Node-RED 只需改连接配置 |

### 2.3 采集引擎能力

| 能力 | 说明 |
|------|------|
| **配置热更新** | 在 RuoYi 改了设备IP → 30秒后 Node-RED 自动用新IP采集，无需重启 flow |
| **采集间隔独立** | 每个设备独立的 `scan_interval_ms`，关键设备1秒，非关键设备5秒 |
| **超时+重试** | `comm_timeout_ms` / `retry_count` / `retry_interval_ms` 三参数控制 |
| **通信方式可切换** | 同一设备可在 MC_Protocol / Modbus_TCP / GOT / RS-232C 间切换 |
| **多协议支持** | 安装对应 Node-RED 节点即可扩展（已装 MC Protocol + Modbus + PostgreSQL） |

## 三、核心优势总结

| 维度 | 纯 Node-RED 拖拽 | EdgeLink (RuoYi + Node-RED) |
|------|-----------------|---------------------------|
| **配置管理** | 散落在 flow 节点属性中 | 集中数据库，Web UI 管理 |
| **修改配置** | 改节点 → 重新 Deploy | 改表单 → Node-RED 自动拉取 |
| **新增设备** | 拖 N 个节点逐个填参数 | 填一个表单 |
| **批量操作** | 逐个节点改 | 勾选 → 批量更新 |
| **删除/恢复** | 删节点=永久丢失 | 软删除，改 del_flag 可恢复 |
| **审计追溯** | 无 | sys_oper_log 完整记录 |
| **权限控制** | 无（谁都能改） | 8个权限码，按角色分配 |
| **备份迁移** | 导出 flow JSON | Excel 导出 + 数据库备份 |
| **团队协作** | 改同一个 flow 冲突 | 各自登录改各自的数据 |
| **扩展性** | 新协议=新节点 | 新协议=新 Node-RED 节点 + 不改配置层 |

## 五、一句话总结

> **纯 Node-RED = 手工作坊**：改一个 IP 要找遍所有节点，20台PLC的配置散落在黑洞里，谁改过不知道。

> **EdgeLink = 工业流水线**：配置在数据库里，表单改完 Node-RED 自动生效。权限、审计、软删除、批量操作、Excel 导入导出——这些纯 Node-RED 拖拽永远做不到。
