## 五、追加变更（同日第二批）：三端口模型 + 工业网 IP 必填

### 背景
现场三个端口角色不同，必须分开建模：
1. **Node-RED 监听端口**：登记时必填（与办公网 IP 合成 hostPcIp）；
2. **PLC 侧目标端口**（plc_port）：添加 PLC 时填，留空走全局默认 `sys_config: plc.mes_port.default`（兜底 5007）；
3. **PC 侧源端口**（local_port，新增）：防火墙严格环境要求 PC↔PLC 走固定源端口，添加 PLC 时选填，留空操作系统自动分配。

## 六、追加变更（同日第三批）：mes_ip 语义修正——自动继承采集点工业网卡 IP

### 问题
PLC 添加页的「工业内网IP *」（`plc_device.mes_ip`）标签与真实语义打架：数据库注释是"MES/MDPS对接IP"，前端却标必填、placeholder 写"PLC同网段的工业网络IP"。且该字段不进配置快照、Node-RED 从未消费——用户填了个没人用的值，还与登记时的采集点工业网 IP 概念重复。

### 修正（用户选定方案：自动继承）
- 语义统一为：**工业内网IP = 采集点工业网卡 IP（indust_ip），每台设备自动继承所属采集点的值**；
- 前端 `device/index.vue`：该输入框改**只读**，选采集点后自动带出（`syncMesIp`），去掉必填星标与必填规则（保留 IP 格式校验）；新增/编辑对话框打开时等下拉加载完自动同步；老数据找不到采集点时保留原值不清空；
- 后端 `device_service.py`：新增/编辑路径去掉 mes_ip 必填（`_require_indust_net_ip` 方法删除），有值仍校验格式；`mes_port` 全局默认逻辑不变；
- `device_do.py`/`device_vo.py` 注释同步改准；
- 数据库 `mes_ip` 列保留不动（老数据不受影响）。

### 验证

## 七、追加变更（09-05/06）：Node-RED 首启引导页 + /auto 真 bug 修复

### 需求与设计定论
用户原案：Node-RED 启动弹引导页，填后端地址+密钥，校验不过则「Node-RED 启动失败」。评审结论：**引导页做，启动阻断不做**——校验失败只阻断采集（configReady 门已存在），不杀进程（后端宕机/网络抖动不能演变成全线停产）。

### 改动清单
| 层 | 文件 | 内容 |
|---|---|---|
| 节点包 | `packages/node-red-contrib-edgelink-bootstrap/` v1.0.0→**v1.1.0** | 新增引导页：`GET /edgelink/guide`（内联单页）、`GET .../api/status`、`POST .../api/activate` |
| 后端 | `module_plc/controller/bootstrap_controller.py` | **修真 bug**：/auto 在 `commit()` 后访问 ORM 属性触发 MissingGreenlet 500（字段先取本地变量再提交） |
| 运维 | `D:\nodered\start-nodered.ps1` | 启动后台轮询 1880，起来后自动打开引导页（注释必须纯英文，ps1 无 BOM 中文会解析炸） |

### 引导页机制
- 激活：页面表单 → 包内服务端调 `/plc/config/bootstrap/auto`（密钥+IP:端口双绑定）→ 通过则写 global context（config-manager 下周期即时生效）+ 落盘 `userDir/edgelink-bootstrap.json`（0600，重启由 bootstrap 节点回读生效）；
- 取值优先级：节点面板 > 引导页落盘文件 > settings.js/环境变量；
- 密钥只写不读：页面永不回显密钥，状态接口只返回 configured 布尔；
- 无 adminAuth 时页面无登录保护（内网前提）；
- 包内拷贝了 detectIp/指纹逻辑（零依赖独立，不引 v13 工作区）。
