# EdgeLink 裸机部署手册（无 Docker）

适用版本：2026-08（初次投产基线）。目标环境：Windows 10/Server 2019+（中心侧与边缘侧同构）。后续再 Docker 化。

## 一、系统组成与数据链路

```
Web 配置（Vue2 + Element UI）
  → 后端（FastAPI，9099）
  → 发布即版本（plc_config_snapshot 快照，保存≠生效）
  → Node-RED 边缘采集（1880；MC/Modbus 协议，30s 轮询兜底 + MQTT 秒级加速）
  → PostgreSQL 时序存储（edgelink.plc_data，断库时磁盘 spool 存储转发）
  → MQTT（EMQX 1883）实时推送 + 监控告警
控制面：kill switch（节点级停用，MQTT 秒级 + 心跳轮询兜底）
```

端口清单（可按需改）：

| 端口 | 组件 | 说明 |
|---|---|---|
| 9099 | 后端 API | FastAPI/uvicorn |
| 80 | 前端 | nginx 托管 dist（生产）/ dev server（开发） |
| 1880 | 边缘 Node-RED | 编辑器 + 边缘本地状态 API（/api/v10/monitor/*） |
| 1883 / 18083 | EMQX | MQTT / 管理 REST |
| 5432 | PostgreSQL | 时序数据 |
| 3308 | MySQL | 业务配置库（本手册示例端口，按实际） |
| 6379 | Redis | 会话/注册窗口 |

## 二、环境要求

- Windows 10/Server 2019+
- Python 3.11（系统安装，勾选 Add to PATH）
- Node.js 18+（边缘侧随 Node-RED 一起；推荐独立目录安装如 `D:\nodered\node.exe`）
- PostgreSQL 14+（时序库）
- MySQL 8（业务库）
- EMQX 5.x（Windows 服务）
- Redis 5+（Windows 服务）
- 全部凭据只在 `.env`（gitignored）与操作系统用户环境变量中存在，**不入库不明文入仓**

## 三、中心侧部署

### 3.1 获取代码

```bash
git clone <主仓地址> RuoYi-Vue-FastAPI
cd RuoYi-Vue-FastAPI
```

目录：`ruoyi-fastapi-backend/`（后端）、`ruoyi-fastapi-frontend/`（前端）、`docs/`（规格/迁移/权威流）、`tools/`（体检与验收脚本）。

### 3.2 MySQL 初始化（库名示例 ruoyi）

```bash
# 1. 建库 + 上游全量种子（系统表/菜单/admin）
mysql -h 127.0.0.1 -P 3308 -u root -p < ruoyi-fastapi-backend/sql/ry-vue-fastapi.sql
# 2. PLC 业务表 + 驱动/协议种子
cd ruoyi-fastapi-backend && python init_plc_db.py
# 3. 按日期顺序执行全部增量迁移（docs/migration_*.sql 与 docs/monitor_center.sql 等）
#    2026-07-19 → 2026-08-22 逐日执行，含：
#    monitor_center.sql / plc_driver.sql / plc_protocol_compat.sql / plc_data_log.sql
#    migration_20260719_*（4 个）/ 20260726_node_health / 20260802_day5_deadband
#    20260820_config_snapshot（发布即版本）/ 20260821_mc_protocol_options
#    20260821_edge_config_version / 20260822_protocol_compat_dedup
#    20260822_calc_tags / 20260822_drop_demo_menus
```

### 3.3 PostgreSQL 初始化

```bash
cd ruoyi-fastapi-backend && python init_pg_db.py   # 建 edgelink.plc_data 等
```

### 3.4 后端

```bash
cd ruoyi-fastapi-backend
python -m venv .venv && .venv\Scripts\activate
pip install -r requirements.txt
copy .env.example .env.dev   # 生产用 .env.production；逐项按下表填写
python app.py --env=prod     # 或 --env=dev
```

`.env` 关键项：

| 键 | 说明 |
|---|---|
| DB_HOST/DB_PORT/DB_USERNAME/DB_PASSWORD/DB_DATABASE | MySQL 连接 |
| REDIS_HOST/REDIS_PORT/REDIS_PASSWORD | Redis |
| MQTT_HOST/MQTT_PORT/MQTT_USERNAME/MQTT_PASSWORD | 后端→EMQX 账号（通知/告警发布） |
| MONITOR_API_KEY | 边缘上报/状态 API 的 X-API-Key（与边缘 EDGE_API_KEY 必须一致） |
| EDGE_COLLECTOR_PASSWORD | 边缘采集账号初始密码（建议投产前改为专用低权账号，见运维纪律） |
| JWT_SECRET_KEY | 随机长串 |

### 3.5 前端

```bash
cd ruoyi-fastapi-frontend
npm ci                 # 注意：package-lock.json 当前被 .gitignore 忽略，若依赖漂移可先 npm install 再构建
npm run build:prod     # 产物在 dist/
```

nginx 托管 `dist/`，关键反代（`/prod-api` → 后端 9099）：

```nginx
location /prod-api/ { proxy_pass http://127.0.0.1:9099/; }
```

### 3.6 EMQX

安装为 Windows 服务后：
```powershell
net start emqx   # 建议管理员执行一次：sc config emqx start= auto（随系统自启）
python tools/restore_emqx_config.py --dashboard-password <EMQX控制台口令>
# 声明式恢复三账号（后端/边缘/前端）+ ACL，幂等可重入；口令从 .env.dev 读取
```

## 四、边缘侧部署（每个采集节点一次）

1. 装 Node.js 与 Node-RED（参考现役机器 `D:\nodered\` 布局）
2. 自研驱动包安装（三个包目录拷入或 npm link 到 `data\node_modules`）：
   - `node-red-contrib-mitsubishi`（MC 协议）
   - `node-red-contrib-edgelink-modbus`
   - `node-red-contrib-edgelink-pg`
3. 部署权威流：`docs/V12/edgelink_v12_main_flow.json` → 边缘 `data\flows.json`；`settings.js` 的 `flowFile` 用**绝对路径**指向它
4. 配置边缘环境变量（用户级，setx 或注册表）：
   `EDGE_API_KEY`（=中心 MONITOR_API_KEY）、`EDGE_BACKEND_USER`、`EDGE_BACKEND_PASS`、`EDGE_BOOTSTRAP_SECRET`、`EDGE_PG_PASSWORD`、`EDGE_MQTT_USERNAME`、`EDGE_MQTT_PASSWORD`
5. 启动器：`start-nodered.ps1`（装载上述变量后启动；带日志版 `start-nodered-log.ps1`）
6. 按压配对自注册：中心侧「边缘节点密钥」页开放注册窗口 → 边缘启动后自动注册并绑定密钥

## 五、服务化（开机自启）

- MySQL/PostgreSQL/Redis/EMQX：本身就是服务；EMQX 记得 `sc config emqx start= auto`
- 后端/Node-RED：用 NSSM 注册为 Windows 服务（`nssm install EdgeLinkBackend ...` 指向 `python app.py --env=prod`；Node-RED 指向启动脚本），或任务计划程序开机启动
- **已知坑**：uvicorn `--reload` 是 supervisor+worker 父子进程，杀 supervisor 不杀 worker 会导致旧代码孤儿进程继续占端口服务。重启后端务必 `taskkill //PID <pid> //T //F`（/T 杀进程树）。生产建议 `--env=prod`（不开 reload）

```bash
# 三个驱动包各自目录下：npm test      # MC 122 / Modbus 56 / pg 9
```

页面人工验收清单见 `docs/初次部署_功能测试报告.md` 第五节。

## 七、日常运维纪律（实战沉淀，必须遵守）

1. **改流双侧同步**：`docs/V12/edgelink_v12_main_flow.json`（权威）与边缘 `data\flows.json` 必须一致，改完重启 Node-RED。`D:\nodered\flows.json` 是旧副本勿用（体检有常驻 WARN 提醒）
2. **发布即版本**：Web 上保存配置不生效，必须到「发布中心」发布；发布中心只列与最新快照有差异的设备，发布后看「边缘已应用版本」卡片确认收敛
3. **任何配置/密钥/EMQX 变更后**跑 `runtime_healthcheck.py`
4. **重启后端用进程树杀法**（`taskkill //T //F`），否则孤儿 worker 继续用旧代码占端口
5. 日志位置：后端 `ruoyi-fastapi-backend/logs/YYYY-MM-DD_error.log`；边缘 `D:\nodered\logs\nodered_console.log`（UTF-16）
6. 中文 Windows 控制台是 GBK：查乱码以字节 hex 为准，勿信控制台显示
7. PowerShell 脚本必须纯 ASCII（GBK 解析 UTF-8 无 BOM 会炸）

## 八、数据保留策略（建议值）

| 数据 | 保留 | 清理方式 |
|---|---|---|
| `nodered_heartbeat_log` | 7 天 | `DELETE ... WHERE report_time < NOW() - INTERVAL 7 DAY` |
| `sys_job_log` / `sys_logininfor` / `sys_oper_log` | 30 天 | 同理按时间列 |
| `monitor_alert` 已恢复（status=2） | 按需（建议 90 天） | 同理 |
| `edgelink.plc_data`（PG） | 按磁盘与业务定（建议 90 天起） | `DELETE FROM edgelink.plc_data WHERE insert_time < ...`，勿用 VACUUM FULL（锁表），依赖 autovacuum |
| 发布/变更履历（plc_publish_log/plc_change_log） | 长期保留（审计） | 不清 |

## 九、备份与回滚

- 备份：MySQL `mysqldump ruoyi > backup.sql`；PG `pg_dump -t edgelink.plc_data postgres > pdata.sql`；边缘 `flows.json` + 环境变量清单（不含值）
- 配置回滚：每次发布的设备+点位快照在 `plc_publish_log.config_snapshot`；回滚 = 把目标版本的配置恢复后重新发布（回滚工具后续提供，当前手工）

## 十、常见故障速查

| 现象 | 排查 |
|---|---|
| 发布后不生效 | 发布中心「边缘已应用版本」卡是否落后；边缘日志 `[CM]`；EMQX 不在时等 30s 轮询 |
| configReady=false | kill switch 是否停用（边缘密钥页）；边缘登录失败（EDGE_BACKEND_*）；看边缘日志 |
| 采集 ECONNREFUSED | PLC/模拟器不在线（检查目标 IP:端口 5007 等） |
| PG 写入停滞 | PG 服务状态；断库期间数据在内存重试缓冲，超 1000 行落 `data\edgelink_pg_spool\`，恢复后自动重放 |
| 告警不收 | 监控中心-告警页；通知通道依赖 EMQX 在线 |
| EMQX 重启/长停后发布只走 30s 轮询 | 边缘 MQTT 订阅可能静默失效（EMQX 启动早期接受连接但授权未就绪，订阅被拒后 Node-RED 不重试）——EMQX 完全就绪后重启 Node-RED，或发布一次看是否 2-3s 收敛来验证；后端通知客户端退避上限 300s，长停后最长 5 分钟才重连 |
| 前端页面字段缺失/异常 | 先硬刷新（Ctrl+F5）排除旧 bundle |
