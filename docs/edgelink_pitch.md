# EdgeLink — 给工业现场带来的实际便利

> 一份给电气工程师、运维人员和工厂管理者的推荐文档

---

## 先看痛点：你现在是不是这样？

**管理 PLC 配置的日常：**

```
桌面上的 Excel 文件: PLC台账_v3_最终版_改2.xlsx
                      PLC台账_v3_最终版_改2_李工.xlsx
                      PLC台账_v3_最终版_改2_李工_修正.xlsx
```

- 20 台 PLC、每台 50 个点位 = 1000 行 Excel，谁改过不知道
- 改一个 IP 地址 → 找到对应行 → 改完 → 通知 Node-RED 负责人 → 他再改 flow
- 新人接手：哪个 Excel 是最新版？在谁电脑里？
- 审计来了：过去半年谁改过 PLC 配置？翻邮件记录吧
- 新增一台 PLC：复制 Excel 行 → 发给 Node-RED 的人 → 等他拖节点 → 等他部署

**这些就是 EdgeLink 要干掉的问题。**

## 一、对电气工程师/PLC 工程师的便利

### 1.1 扔掉 Excel，用 Web 表单管设备

| 以前 | 现在 |
|------|------|
| Excel 单元格填参数，格式没校验，IP 写错没人提醒 | Web 表单自动校验：IP 格式不正确会弹红字提醒，FX 系列选 4E 帧自动阻止 |
| 新增一台 PLC：打开 Excel → 找到底部的空白行 → 一个单元格一个单元格填 | 新增一台 PLC：点「新增」→ 填 3 个 Tab（基本属性/网络配置/采集参数）→ 确定 |
| 克隆一台相似的 PLC：复制行 → 改设备名 → 改 IP → 改编号 → 再手动复制下面 50 行点位 | 克隆一台：点「克隆」→ 输新名称和 IP → 确定。**设备+全部点位 3 秒搞定** |

### 1.2 批量操作，不用逐行改

| 场景 | 以前 | 现在 |
|------|------|------|
| 产线升级，20 台 PLC 采集周期从 1000ms 改为 500ms | 打开 Excel → 找到每台设备 → 改 20 次 | ⚠️ Phase 2 功能（已规划 `PUT /plc/device/batch`） |
| 50 个点位的数据类型从 INT16 改为 FLOAT | Excel 筛选 → 逐行改 50 次 | 勾选 50 个点位 → 批量修改 → 选数据类型 → 确定 |
| 新产线上线，按模板导入 200 个点位 | 手打 200 行 | 下载模板 Excel → 填好 → 上传导入。成功/失败分明细显示 |

### 1.3 不怕改错，不怕删错

- **软删除**：删除的数据还在数据库里，改 `del_flag` 就能恢复。不像 Excel 删了行只能翻历史版本
- **启停开关**：想暂停某台 PLC 的采集？点一下开关就行，数据保留，随时可以再打开
- **克隆 = 快照**：调试前先克隆一份，调坏了不影响原设备

## 二、对运维/Node-RED 负责人的便利

### 2.1 改配置不再需要改 flow

**这是最大的变革。**

| 以前 | 现在 |
|------|------|
| 电气工程师说"3号线 PLC 换 IP 了" → 你打开 Node-RED → 找到对应的 MC Read 节点 → 改 IP → Deploy | 电气工程师自己在 RuoYi 后台改 IP → Node-RED **30 秒后自动用新 IP 采集**。你连浏览器都不用打开 |
| 新增一台 PLC → 你要拖 MC Connection 节点 → 拖 MC Read 节点 → 填参数 → 连线 → Deploy | 电气工程师在 RuoYi 填表单 → Node-RED 自动识别新设备 → 开始采集 |

**你的 Node-RED flow 部署后就不用动了。** 配置变更全部在 RuoYi 后台完成，Node-RED 从数据库动态拉取。

### 2.2 出问题能追溯

- 谁在什么时候把 PLC 的 IP 改错了导致采集中断？→ `sys_oper_log` 查：`张三 2026-06-07 14:32 修改PLC设备 IP: 192.168.1.100 → 192.168.1.10`
- 纯 Node-RED：翻 flow 的修改记录？Node-RED 没有这个功能

## 三、对管理者/审计的便利

### 3.1 权限分级

| 角色 | 能做什么 | 不能做什么 |
|------|---------|-----------|
| 操作员 | 查看设备列表、查看点位 | 不能新增、修改、删除 |
| 电气工程师 | 新增/修改设备、管理点位、导入导出 | 不能删除设备 |
| 管理员 | 所有操作 + 分配权限 | — |

纯 Node-RED 只有一种权限：打开 `:1880` 的人什么都能干。

### 3.2 完整的操作日志

每次新增、修改、删除、导入、导出都有记录：

```
操作人: 李工
操作: 修改PLC设备
时间: 2026-06-07 14:32:15
IP: 192.168.1.101
内容: {"deviceName": "3号线主机", "plcIp": "192.168.1.100", ...}
耗时: 45ms
```

合规审查时直接导出，不用翻邮件、翻 Excel、翻聊天记录。

## 四、对比：一天的工作量

**场景：新增一条产线（5 台 PLC × 50 点位）**

| 步骤 | 纯 Excel + Node-RED | EdgeLink |
|------|-------------------|----------|
| 新增 5 台PLC配置 | Excel 逐行填写 5×25=125 个字段 | RuoYi 表单填 5 次，每个 3 Tab |
| 克隆相似设备 | 复制 Excel 行 → 手动改差异 | 克隆按钮 → 只填名称+IP |
| 新增 250 个点位 | Excel 填写 250 行 | 下载模板 → 批量填写 → 上传导入 |
| 通知运维配置 Node-RED | 微信/邮件 → 等回复 → 他拖节点 | **不需要** |
| Node-RED 改 flow | 拖 5 个 MC Connection + 250 个 MC Read → 连线 → Deploy | **不需要** |
| 全程耗时 | **~4 小时**（含等待和沟通） | **~30 分钟**（都在 Web 操作） |

## 六、怎么给别人演示

### 演示 1：新增设备 → 自动采集

1. 打开 RuoYi → 连接配置 → PLC设备管理 → 新增
2. 填：设备名 `Demo-PLC`、IP `192.168.1.200`、系列 `Q`、通信方式 `MC_Protocol`、帧格式 `3E`
3. 点位管理 → 新增几个点位（D100, D200, X0）
4. 切到 Node-RED → Debug 面板 → **30 秒内出现新设备的数据**

> "看，我没碰 Node-RED，只是填了个表单，采集就自动开始了。"

### 演示 2：克隆设备

1. 点克隆 → 填新名称 `Demo-PLC-2`、新 IP `192.168.1.201`
2. 确定
3. 刷新列表 → 新设备出现，全部点位已复制

> "原来要复制 Excel + 通知运维，现在 3 秒。"

### 演示 3：启停控制

1. 点设备列表的状态开关 → 关闭
2. Node-RED 停止采集该设备
3. 再打开 → 恢复采集

> "临时停采不需要删配置，一个开关的事。"

### 演示 4：权限控制

1. 用操作员账号登录 → 看不到新增/修改/删除按钮
2. 用管理员账号登录 → 全部按钮可见

> "不同角色看到不同的界面。"
