# 存量监控增强变更说明（2026-09-20）

## 需求

1. 健康度监视节点上报时同时携带 Node-RED 的 **error 级报错信息**（只报 error，监控页列表标黄提示即可，不做已读机制）。
2. 新增一个 **flows.json 上传节点**：与健康度节点同处调色板「存量监控」分类，点击按钮输入上传原因后上传本机 flows.json，后端记录上传时间，每站点保留最近 **5 份**。
3. 两个节点**共享配置**（服务器/端口/前缀/HTTPS/Key 只填一次）。

## 改动清单

### 节点包 `packages/node-red-contrib-edgelink-site-health`（v1.0.6 → v1.1.2）

> **v1.1.2 紧急修复（21:44 真机崩溃）**：`RED.log.addHandler` 收的是 **EventEmitter**——运行时对每条日志调 `handler.emit('log', msg)`，v1.1.0/1.1.1 传普通函数导致 Node-RED 启动后第一条日志即抛 `handler.emit is not a function` 崩进程。已改为 `new EventEmitter() + emitter.on('log', fn)`，并用真实 @node-red/util log 模块回归验证（trace/info/warn/error/fatal 全级别 + close 摘除后主链路正常）。v1.1.0/1.1.1 的 tgz **禁止使用**。

### 数据库

- 迁移脚本：`docs/9-20/migration_20260920_site_health_errors_uploads.sql`（已有库执行一次；新建库 create_all 自动包含）
- **无菜单变更**（权限复用 `site:health:list`），用户无需重新登录
- **utf8mb4 修复（21:08 实测发现）**：flows.json / error 日志含 emoji 等 4 字节字符，MySQL 默认 utf8（3 字节）报 1366——`site_health_flows_upload` 建表指定 utf8mb4，`last_errors` 列指定 utf8mb4，模型 `__table_args__` 加 `mysql_charset` 兜底新装库；旧库用脚本末尾两句 ALTER 修复

## 部署 / 升级步骤

1. 执行迁移 SQL；
2. 重启后端（`create_all` 对新库自动建表，旧库必须先跑 SQL 再重启）；
3. 前端重新构建部署；
4. 现场 Node-RED 安装 `node-red-contrib-edgelink-site-health-1.1.0.tgz` 并重启：
   - 老「采集点健康度」节点不动即可继续工作（回落旧字段）；
   - 建议新建「存量监控服务器」共享配置（填 Key），两个节点引用它。

## 兼容性

- 旧 1.0.x 节点 → 新后端：只发 query 无 body，行为不变 ✅
- 新节点 → 旧后端：errors body 被忽略；`/flows/upload` 404，节点红灯提示 ⚠️（需配套升级后端）
- flows.json 含现场敏感拓扑：仅 `site:health:list` 权限可下载；节点 key 只可上传不可读取
