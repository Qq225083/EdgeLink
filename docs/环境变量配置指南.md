# EdgeLink 环境变量配置指南

> 本文档说明后端、前端、Node-RED 三端环境变量的配置方式，用于开发、测试、生产部署。

---

## 1. 后端环境变量（ruoyi-fastapi-backend）

### 1.1 文件说明

| 文件 | 用途 | 是否纳入版本控制 |
|---|---|---|
| `.env.example` | 环境变量模板 | ✅ 是 |
| `.env.dev` | 开发环境配置 | ❌ 否（.gitignore） |
| `.env.prod` | 生产环境配置 | ❌ 否（.gitignore） |
| `.env.staging` | 预发布环境配置 | ❌ 否（.gitignore） |

### 1.2 必配项（生产环境）

| 变量 | 说明 | 生成方式 |
|---|---|---|
| `APP_ENV` | 运行环境 | `prod` |
| `JWT_SECRET_KEY` | JWT 密钥，≥32 位 | `python -c "import secrets; print(secrets.token_hex(32))"` |
| `MONITOR_API_KEY` | Node-RED 监控上报 API Key | `python -c "import secrets; print(secrets.token_hex(32))"` |
| `DB_PASSWORD` | 数据库密码 | `python -c "import secrets; print(secrets.token_urlsafe(16))"` |
| `MQTT_USERNAME` | MQTT 用户名 | EMQX 管理界面创建 |
| `MQTT_PASSWORD` | MQTT 密码 | EMQX 管理界面创建 |

### 1.3 启动方式

```bash
# 开发环境
export APP_ENV=dev
python app.py

# 生产环境（方式一：环境变量）
export APP_ENV=prod
python app.py

# 生产环境（方式二：命令行参数）
python app.py --env=prod

# 生产环境（方式三：uvicorn）
APP_ENV=prod uvicorn app:app --host 0.0.0.0 --port 9099
```

### 1.4 未设置 APP_ENV 的行为

从 2026-07-19 起，未设置 `APP_ENV` 时启动会抛出异常，不再默认加载 `.env.dev`。

错误示例：
```
ValueError: APP_ENV 未设置，无法确定加载哪个环境配置文件。
```

## 2. 前端环境变量（ruoyi-fastapi-frontend）

### 2.1 文件说明

| 文件 | 用途 | 是否纳入版本控制 |
|---|---|---|
| `.env.example` | 环境变量模板 | ✅ 是 |
| `.env.development` | 开发环境配置 | ❌ 否 |
| `.env.production` | 生产环境配置 | ❌ 否 |

### 2.2 必配项（生产环境）

| 变量 | 说明 | 示例 |
|---|---|---|
| `VUE_APP_MQTT_WS_URL` | MQTT WebSocket 地址 | `wss://emqx.example.com:8084/mqtt` |
| `VUE_APP_MQTT_USERNAME` | MQTT 用户名 | `web_sub` |
| `VUE_APP_MQTT_PASSWORD` | MQTT 密码 | `your-strong-password` |

### 2.3 构建方式

```bash
# 开发
npm run dev

# 生产
npm run build:prod
```

## 3. Node-RED 环境变量（采集节点）

### 3.1 配置方式优先级

1. **后端 Bootstrap 下发（推荐，Day 7 实施）**
   - Node-RED 首次启动时调用 `/plc/config/bootstrap` 拉取完整配置
   - 后续配置变更通过「配置发布中心」统一下发
   - 每台 PC 只需设置初始 `X-Bootstrap-Key`

2. **settings.js functionGlobalContext（当前方式）**
   - 文件：`D:/nodered/data/settings.js`
   - 适合单台或少量采集 PC

3. **系统环境变量**
   - Windows：`set EDGE_HOST_PC_IP=192.168.1.3:1880`
   - Linux：`export EDGE_HOST_PC_IP=192.168.1.3:1880`

### 3.2 必配项（每台采集 PC）

| 变量 | 说明 | 示例 |
|---|---|---|
| `edge_nodeId` | 节点数字 ID（唯一） | `1001` |
| `edge_hostPcIp` | 节点标识（IP:端口） | `192.168.1.3:1880` |
| `edge_backendHost` | 后端地址 | `192.168.1.10` |
| `edge_backendPort` | 后端端口 | `9099` |
| `edge_apiKey` | Monitor API Key | 与后端 `MONITOR_API_KEY` 一致 |
| `edge_backendUser` | 后端登录用户名 | `admin` |
| `edge_backendPass` | 后端登录密码 | 与后端 `DB_PASSWORD` 无直接关系，是应用登录密码 |

### 3.3 多实例部署

一台 PC 跑多个 Node-RED 实例时，每个实例必须有独立的：

```javascript
// settings_1880.js
functionGlobalContext: {
    edge_nodeId: 1001,
    edge_hostPcIp: '192.168.1.3:1880'
}

// settings_1881.js
functionGlobalContext: {
    edge_nodeId: 1002,
    edge_hostPcIp: '192.168.1.3:1881'
}
```

启动：
```bash
node-red -s settings_1880.js -p 1880
node-red -s settings_1881.js -p 1881
```

## 4. 密钥生成命令汇总

```bash
# JWT_SECRET_KEY（32 字节 hex，64 字符）
python -c "import secrets; print(secrets.token_hex(32))"

# MONITOR_API_KEY（32 字节 hex，64 字符）
python -c "import secrets; print(secrets.token_hex(32))"

# DB_PASSWORD（16 字节 base64，22 字符）
python -c "import secrets; print(secrets.token_urlsafe(16))"

# X-Bootstrap-Key（16 字节 hex，32 字符）
python -c "import secrets; print(secrets.token_hex(16))"
```

## 5. 安全检查清单

部署前请确认：

- [ ] `.env.prod` 中无默认值、无弱密码
- [ ] `JWT_SECRET_KEY` 为强随机，未泄露在代码或日志中
- [ ] `MONITOR_API_KEY` 为强随机，与 Node-RED 配置一致
- [ ] `DB_PASSWORD` 为强随机，未使用常见弱密码
- [ ] MQTT 使用 `wss://`（生产环境）而非 `ws://`
- [ ] Node-RED `settings.js` 中无明文密码（已迁移至 bootstrap 下发）
- [ ] 前端构建产物中无 `VUE_APP_MQTT_PASSWORD` 硬编码
