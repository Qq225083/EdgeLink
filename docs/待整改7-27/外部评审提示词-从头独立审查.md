## 二、核心数据流（审查必须追踪的路径）

1. 设备/点位保存（前端表单 → device/tag service → DB）→ 发布中心手动发布 → MQTT CONFIG_REFRESH → Node-RED config-manager（登录 → 分页拉点位 → 按 driverCode/comType 分流）→ 调度器（每设备 scanIntervalMs）→ 协议读写节点（mitsubishi-read/write、modbus-read/write）→ data-processor（换算/死区/强制/质量码）→ PG 格式转换 → pg-store（批量 INSERT + 磁盘 spool 兜底）
2. 监控：心跳（30s，含 PG 统计/spool 积压）→ /monitor/heartbeat → nodered_node + 离线检测（APScheduler 30s + MQTT LWT）→ 告警 create/resolve（monitor_alert 唯一约束）→ 前端监控页（MQTT + 轮询）
3. 节点生命周期：bootstrap 密钥 → /plc/config/bootstrap 下发配置 → edge_collector 登录；停用下发 NODE_STATUS（kill switch）

## 三、审查维度（每个都要覆盖并给出结论）

A. **功能正确性**：状态机（启用/停用/软删除/重开）、批量操作边界、分页、数据类型转换（INT16/32/UINT/FLOAT32/DOUBLE/BOOL × byteOrder/wordOrder/bitOffset）真机语义、读写两侧
B. **架构设计**：配置驱动是否闭环、边缘/云职责、协议可插拔（plc_driver）是否名副其实
C. **数据库与 ORM**：索引、事务边界、commit 后访问 ORM 属性的 MissingGreenlet 类问题、N+1、时序表膨胀与生命周期
D. **并发与性能**：MC/Modbus 连接池（泄漏/竞争/重连风暴/close 守卫）、调度器并发、MQTT 洪峰、spool 竞态
E. **安全**：SQL 注入、鉴权（JWT/密钥/edge_collector 权限粒度）、凭据存储、注入面（表名/列名拼接）
F. **错误处理与可观测性**：静默吞异常、失败语义（quality 标记 vs 缺席）、日志可定位性
G. **前后端契约**：camelCase/snake_case 分页参数、枚举对齐、单位语义
H. **可维护性**：重复代码、单文件规模、配置外部化、注释与实现一致性

## 四、建议的深查方向（不限于此）
